# PLE-663: `stream_decoder_qcom_vt_low_latency` off/on on the Oculus Go (partial)

This is the `vt-low-latency` A/B that PLE-635 set up but did not run. It used PLE-635's display-0
`go-ab.sh` recipe (see the appendix of `PLE-635.md`) with `SECS=45`, the first 5 stats windows
skipped, a live PS5-466 stream, 1920x1080 at 60 fps, and 10.7 Mbps measured.

* Device: Oculus Go `192.168.1.202:5555` (serial `1KWPH802EW8203`), Android 7.1.1.
* Build: this branch's `app-debug.apk` after rebasing onto `fork/android-port` (`a16a5876`), gate PASS.
* Session 1 ran on 2026-09-27 from 03:38 to 03:42 UTC. The per-arm session logs and logcat are in
  the worktree under `build/ple663/run1/` (gitignored).

**What one run shows:** with HEVC, `vt-low-latency` is within noise: -0.08 ms mean, and the
window-mean ranges overlap. H.264 decodes about 3.3 ms slower than HEVC on this decoder, with
`vt-low-latency` off. That is a single run per arm, so it is not a result.

## Why it stopped

At 03:41:48 UTC, at the end of arm E's 45 s stream, the Go dropped off the network. The
last logcat line is 06:41:48 in device time. From then on, `adb shell` hung, even though
`adb devices` still listed the Go as `device`. `adb connect 192.168.1.202:5555` then failed
with `No route to host`, and kept failing for more than 10 minutes, until 04:04 UTC. Arm F,
run 2 and the `restore` step never ran.

**The Go is left dirty:** it has this branch's debug APK, and its prefs may be arm E's (H.264 +
stats log), because the restore readback failed. The pre-session snapshot (prefs, databases,
base.apk versionCode 12, installed 2026-09-27 06:07 device time) is in
`~/.config/pleikkari/backups/go-ple663-before-20260927T0338Z/` on CT950. To restore it, run
`BACKUP=<that dir> bash go-ab.sh <out> restore` under the Go lease. Its `restore` step only
runs when `setup` ran in the same invocation, so run `setup restore`. `setup` keeps an
existing snapshot.
